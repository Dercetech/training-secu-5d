Header 2/5 · Lab local

Le navigateur ne doit pas deviner

Deux ressources sont bien renvoyées par l’API, mais le serveur a oublié leur Content-Type. Avec X-Content-Type-Options: nosniff, le navigateur refuse de les interpréter à l’aveugle.

JavaScript

Le script est-il exécuté ?

JavaScript non exécuté : vérifiez le type MIME dans Network et la Console.

Feuille de style

Le CSS est-il interprété ?

CSS non interprétée : la carte conserve son apparence d’alerte.

CSS interprétée : la carte devient verte.

Travail demandé

Corriger le contrat HTTP, pas le navigateur

  1. Dans DevTools → Network, ouvrez les réponses script et styles.
  2. Confirmez que leur contenu arrive bien et que X-Content-Type-Options vaut nosniff.
  3. Dans le serveur Flask ou Express, donnez à chaque réponse son type réel : JavaScript ou CSS.
  4. Conservez nosniff, redémarrez le serveur, puis rechargez la page sans cache.

Ne trichez pas avec l’URL : ajouter une extension .js ou .css ne remplace pas un vrai response header Content-Type.

Pourquoi ce refus est une bonne chose

Si le serveur annonce mal une ressource, le navigateur n’essaie pas de déduire son rôle depuis son contenu. Une réponse inattendue ne devient donc pas automatiquement un script exécutable.

nosniff ne répare pas le serveur : il rend l’erreur visible et exige un contrat HTTP correct.
