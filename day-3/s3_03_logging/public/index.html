La connexion dangereuse active un logger qui recopie tous les headers « pour la traçabilité ». L’équipe croyait que l’authentification resterait toujours dans un cookie.

Autre transport

localStorage.setItem("audit_lab_jwt", token)

Authorization: Bearer <token>

Avec Bearer, le front conserve la chaîne et ajoute lui-même le header. Le navigateur ne le fait pas automatiquement.

Avis d’architecte : pour une application web classique same-origin, je préfère généralement un cookie HttpOnly, Secure et SameSite. Un Bearer dans localStorage est pratique pour certains clients API, mais une XSS peut le lire. Ce n’est pas « plus moderne » par défaut : c’est un compromis différent.
