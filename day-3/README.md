# Jour 3 — API, autorisations et configuration web

Le Jour 3 suit le programme présenté en classe. Chaque laboratoire reste local,
utilise des données fictives et propose les mêmes deux saveurs : Flask ou
Express, avec une interface partagée dans `public/`.

```text
s1_01_jwt          Modifier un JWT, puis vérifier sa signature et ses dates
s2_01_idor         Observer un IDOR, puis appliquer un middleware d’autorisation
s3_01_cors         Comprendre l’origine et une liste CORS explicite
s3_02_secrets      Lire un secret depuis l’environnement sans l’exposer
s3_03_logging      Comparer un journal indiscret à un journal minimal
s3_04_headers      Observer puis ajouter des headers de sécurité du navigateur
```

La convention des dossiers est `s<section>_<numéro>_<mots-clés>`. Les exemples
montrent des erreurs fréquentes afin de les reconnaître et de les corriger. Ils
ne doivent jamais être déployés comme applications réelles.

Les corrections complètes sont séparées des laboratoires :

```text
z_solutions/d3/s1_01
z_solutions/d3/s2_01
z_solutions/d3/s3_01
z_solutions/d3/s3_02
z_solutions/d3/s3_03
z_solutions/d3/s3_04
```

Consultez `z_solutions/d3/README.md` pour leur contenu et leur lancement.
